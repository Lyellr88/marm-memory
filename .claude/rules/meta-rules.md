# Rule Writing Rules

## Do's

**Keep all rules concise - deliver data without bloat**  
**Direct statements: "Do X", "Never Y", "Always Z"**  
**Essential info only - no verbose explanations**  
**Scan rules to suggest updates or new rules based on current session**

## Don'ts

**Don't run tests on smaller quick edits - only on full refactors or new features. Also skip running line and typechecks**
**No frontmatter, examples, or "why" sections**  
**No redundant context or explanatory fluff**
**Never Use Em-Dashes**
**Comments in code keep to a minimum - only when necessary for clarity**

**Goal:** Maximum actionable guidance per token. Rules = behavioral constraints, not documentation.
